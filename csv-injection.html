CSV Injection

What it is

A site exports user data to a CSV file, and a cell starting with =, +, - or @ gets treated as a formula when someone opens it in a spreadsheet. The harm happens on the victim's computer, not on the server. OWASP: A03 Injection. CWE-1236.

The line

// export.js: builds the CSV an admin downloadsfunction exportCsv(customers) {  const rows = customers.map(c => {    const name = c.name;    return `"${name.replace(/"/g, '""')}",${c.email}`;  });  return ["name,email", ...rows].join("\n");}

Try it

Why it matters

An attacker signs up with a formula as their name. Later an admin exports the customer list and opens it. A formula can show a fake link, or in the worst cases pull data from other cells and send it out. The server is never hacked, so logs show nothing. Some vendors call this low risk because the victim must open the file, but admins open exports all the time.

The fix

// export.js: builds the CSV an admin downloadsfunction exportCsv(customers) {  const rows = customers.map(c => {    const name = /^[=+\-@\t\r]/.test(c.name) ? "'" + c.name : c.name;    return `"${name.replace(/"/g, '""')}",${c.email}`;  });  return ["name,email", ...rows].join("\n");}
