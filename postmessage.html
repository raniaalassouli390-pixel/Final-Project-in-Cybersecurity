Insecure postMessage

What it is

Pages and iframes talk to each other with postMessage, and the receiver must check who sent each message using event.origin. If it does not, any website can send commands that your page will obey. OWASP: A01 Broken Access Control. CWE-346 (Origin Validation Error).

The line

// account.js: answers requests from the embedded widgetconst token = "demo-token-1234";window.addEventListener("message", (e) => {  // no check of e.origin: anyone can ask  if (e.data.action === "getToken") {    e.source.postMessage({ token }, "*");  }});

Why it matters

A malicious site can open yours in a hidden iframe or pop-up and send it messages. If your page answers with something private, like a session token, the attacker can take over the account. Users see nothing, because the messages never appear in the address bar. A wrong check is almost as bad as none: a rule like "origin contains bank.example" also accepts bank.example.evil.com. Always compare against an exact allowlist, and never reply with target "*".

The fix

// account.js: answers requests from the embedded widgetconst ALLOWED = ["https://bank.example"];const token = "demo-token-1234";window.addEventListener("message", (e) => {  if (!ALLOWED.includes(e.origin)) return;  if (e.data.action === "getToken") {    e.source.postMessage({ token }, e.origin);  }});
